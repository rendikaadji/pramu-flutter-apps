# 03 - Celah Keamanan Mobile (review desain)
> **USANG (29 Oktober 2026):** dokumen ini mengikuti model lama (lowongan, lamaran, wawancara, SKCK, escrow). Sumber aturan produk sekarang satu: [PRD Web v1.3](https://github.com/rendikaadji/pramu-laravel-web/blob/main/Docs/01-PRD-Web.md) dan [Skema Database](https://github.com/rendikaadji/pramu-laravel-web/blob/main/Docs/12-Skema-Database.md) di repo pramu-laravel-web. Dokumen ini ditulis ulang per modul saat app dibangun ulang (keputusan K-47).

> **Perubahan lingkup 2026-10-28:** penampungan dana (escrow) dihapus: bayar periode, konfirmasi selesai, auto-release, dompet, rekening bank, tarik dana, batal+refund, potongan platform 10%, dan sengketa dana **tidak berlaku lagi** (layar M-74..76, M-80..83). Kesepakatan, kontrak (tanpa uang), biaya tayang lowongan, dan rating tetap. Acuan terbaru: [[01-PRD-Mobile]] dan [[09-Arsitektur-App]].

> Acuan: [[PRD-v1]] dan [[Spec-Teknis-v1]] (§2, §3, §8 FCM/Xendit, §9). Pasangan: Web/03-Celah-Keamanan-Web. Standar: OWASP MASVS v2 (kategori STORAGE, CRYPTO, AUTH, NETWORK, PLATFORM, CODE, RESILIENCE, PRIVACY) dan panduan uji MASTG.
> **Repo `asisten-mobile` belum ada.** Semua temuan = *risiko desain*, bukan bug terbukti. Setiap temuan punya cara verifikasi saat build ada. Tanpa exploit; hanya kelas serangan + mitigasi.

## 1. Ringkasan & threat model

**Aset di perangkat:** token Sanctum (akses akun, termasuk payout) · foto KTP/selfie/SKCK saat diambil & diunggah · isi chat yang ditampilkan/di-cache · `meeting_url` · nomor rekening saat input · token FCM · state pembayaran (invoice_url).

**Aktor:** pencuri/peminjam ponsel (akses fisik, lock screen) · malware/aplikasi lain di ponsel yang sama (deep link hijack, clipboard, overlay) · pengguna berniat curang yang me-root perangkat dan memodifikasi app (bypass UI, replay API) · penyerang jaringan (Wi-Fi publik, proxy/MITM) · analis reverse-engineering (APK/IPA publik).

**Trust boundary:** (1) app <-> API (jaringan tak tepercaya, klien tak tepercaya: **semua aturan bisnis dan uang wajib ditegakkan server**); (2) app <-> OS (storage, keychain, IPC/deep link, backup); (3) app <-> aplikasi lain (intent, URL scheme, clipboard); (4) app <-> halaman pembayaran Xendit (WebView/browser) dan Google Meet (aplikasi eksternal); (5) app <-> FCM/APNs.

**Prinsip:** klien dianggap sudah dikuasai penyerang; kontrol di app hanya memperlambat (defense in depth), bukan batas keamanan. Server tetap sumber kebenaran status bayar, role, harga, dan kepemilikan (lihat Web WEB-SEC-03/13).

## 3. Checklist verifikasi kode & build (saat repo ada)

Jalankan dari root `asisten-mobile`. `rg` = ripgrep (atau `grep -rn`). Dinamis hanya pada perangkat/emulator dan build staging milik sendiri.

**Statis (sumber)**
- [ ] `flutter analyze` (aktifkan lint `avoid_print`); `flutter pub outdated`; `flutter pub deps --style=compact`.
- [ ] `rg -n "SharedPreferences" lib/` dan `rg -n "flutter_secure_storage" lib/ pubspec.yaml` (token hanya di secure storage).
- [ ] `rg -n "print\(" lib/`; `rg -n "debugPrint\(" lib/`; `rg -n "LogInterceptor" lib/`.
- [ ] `rg -n "badCertificateCallback" lib/`; `rg -n "http://" lib/`; `rg -n "ws://" lib/`.
- [ ] `rg -n "webview_flutter" pubspec.yaml lib/`; `rg -n "launchUrl" lib/`.
- [ ] `rg -n "image_picker" lib/` + pastikan file sementara dihapus setelah unggah.
- [ ] `rg -n "allowBackup" android/app/src`; `rg -n "usesCleartextTraffic" android/app/src`; `rg -n "exported" android/app/src`; `rg -n "debuggable" android/`; `rg -n "autoVerify" android/app/src`.
- [ ] `plutil -p ios/Runner/Info.plist` (ATS, URL types, usage descriptions) dan entitlements (`applinks:`).
- [ ] `gitleaks detect --source . --redact`; `git ls-files` tidak memuat keystore (`.jks`), `key.properties`, `.p12`.

**Build rilis**
- [ ] `flutter build appbundle --release --obfuscate --split-debug-info=build/symbols` (iOS: `flutter build ipa --obfuscate --split-debug-info=build/symbols`).
- [ ] `apkanalyzer manifest print <apk>` dan `apkanalyzer manifest permissions <apk>` (exported, backup, permission); `apksigner verify --print-certs <apk>`.
- [ ] `jadx -d out <apk>` + `strings` pada `libapp.so`: tak ada secret, nama kelas bisnis terobfuscate.
- [ ] `mobsfscan .` (bila terpasang) sebagai pemindai statis tambahan.

**Dinamis (perangkat uji)**
- [ ] Proxy MITM milik sendiri: koneksi staging harus gagal (pinning) dan tak ada token di URL.
- [ ] `adb logcat` selama login/upload/bayar: tak ada token/OTP/NIK.
- [ ] Setelah unggah KTP: direktori cache/files app tidak berisi gambar KTP; unggahan di server bebas EXIF.
- [ ] Deep link palsu (`adb shell am start -a android.intent.action.VIEW -d "<link>" <package>`) tak menandai pembayaran lunas.
- [ ] Layar KTP: screenshot diblok (Android) / app switcher tersamar (iOS).
- [ ] Logout lalu login akun lain: tak ada data akun sebelumnya; token lama 401.
- [ ] Push dengan `type`/ID palsu pada proyek Firebase uji: tak crash, tak menampilkan data asing.

## 4. Gerbang go/no-go sebelum live (mobile)

**NO-GO bila:**
1. MOB-SEC-01 s.d. 07 (High) belum tertutup atau tanpa penerimaan risiko tertulis.
2. Build rilis tidak memakai obfuscation + split-debug-info, atau `allowBackup`/`usesCleartextTraffic` aktif, atau komponen `exported` tak terdaftar.
3. Token tersimpan di luar secure storage; pembayaran dinyatakan sukses dari deep link tanpa cek API.
4. Pinning belum diuji di staging (termasuk rencana rotasi/force-update) atau ada override sertifikat di release.
5. Foto KTP/selfie tersisa di cache/galeri setelah unggah; EXIF belum dibuang.
6. Ada rahasia server di binary; keystore rilis tidak aman atau ada di repo.
7. Data Safety (Play) dan Privacy Labels (App Store) belum selaras dengan kebijakan privasi UU PDP (Web WEB-SEC-15).
8. Checklist dinamis belum dijalankan pada Android **dan** iOS fisik (Spec §10).

**GO bersyarat:** Medium punya tiket + pemilik + tenggat <= 30 hari; Low backlog. Kontrol server Web (WEB-SEC-01..03) wajib lebih dulu karena kontrol mobile bisa dilewati.
